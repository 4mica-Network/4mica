4Mica v2 is live on Base mainnet. It fixes the three things that keep APIs
off x402 today.

- **Charge what the job actually cost.** x402 needs a price before the work
  starts. Most of what agents buy, from model calls to scrapes to multi-step
  runs, has no price until it finishes, so providers can't sell it over x402.
- **No gas and no wait, on every request.** A payment is a cryptographic guarantee
  against collateral the agent has already deposited. Nothing touches the
  chain, so a request costs no gas and is served immediately, globally.
- **One settlement a day, without holding ETH.** Every participant settles
  its net position once every 24 hours, on Base and on each chain that
  follows. Deposits, withdrawals and the daily settlement all run gaslessly,
  so an agent needs nothing but stablecoins.

## How 4Mica works (differently)

Take one job: an agent asks a scraping API to crawl a site. The provider can't
know the price until the crawl is done. Say it ends up costing $0.37, and the
agent is willing to spend up to $1.00.

**With x402 today, the provider has two bad options.** With `exact`, it quotes
a price before the work and the agent pays it up front. Quote $1.00 and the
agent overpays by $0.63. Quote $0.37 and the provider can't, because it doesn't
know the price yet. With `upto`, the agent signs an allowance of up to $1.00,
but nothing holds that dollar while the crawl runs. The same balance can back
any number of other signatures, and the provider only finds out whether it
gets paid after it has done the work.

**With 4Mica, the agent authorizes a cap and pays for what was used.** The
agent authorize the cap of $1.00, which is locked until job is done. The
provider runs the crawl, charges $0.37, and agent can use the $0.63 for the next task.
The provider is covered before it starts work, and the agent pays
for exactly what it used.

**A payment is a guarantee, not a transfer.** What the agent hands over with
the request is a cryptographic guarantee: a signed promise to pay. The provider can verify it on
its own, without trusting the agent or calling a chain. If the agent never
pays, the locked collateral does. Since nothing moves on-chain at this point,
the request costs no gas and gets an answer in the time a signature check
takes.

**The money moves once a day, in one batch.** Guarantees collect over a 24-hour
cycle. When the cycle closes, 4Mica nets everything each participant owes and
is owed, across every counterparty, and commits the result on-chain.

## What it takes to integrate

An agent deposits once and keeps the `fetch` it already has. Every 402 it meets
from a 4Mica provider is then paid automatically, with no account to create and
no key to store:

```typescript
import { FourMicaEvmScheme } from "@4mica/x402/client";
import { wrapFetchWithPaymentFromConfig } from "@x402/fetch";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount("0xYourPrivateKey");
const scheme = await FourMicaEvmScheme.create(account);

const fetchWithPayment = wrapFetchWithPaymentFromConfig(fetch, {
  schemes: [{ network: "eip155:84532", client: scheme }],
});

const response = await fetchWithPayment("https://api.example.com/data");
```

A provider adds one middleware and sets a price per route. There is no billing
system, no customer database and no key management to build:

```typescript
import { paymentMiddlewareFromConfig } from "@4mica/x402/server/express";

app.use(
  paymentMiddlewareFromConfig({
    "GET /data": {
      accepts: {
        scheme: "4mica-credit",
        price: "$0.01",
        network: "eip155:84532",
        payTo: "0xYourAddress",
      },
    },
  }),
);
```

A flat price is the simplest place to start. The
[metered billing demo](/blog/answering-x402-three-problems) runs the
cap-and-refund flow from the crawl example end to end.

## One settlement a day, on Base and every chain after it

Because the money moves once a day, settlement does not grow with the number of
the number of requests. An agent that made a million
requests across a hundred APIs settles once that day, and so does each API.

The provider never waits on that settlement to get paid safely. The amount was
locked before the work started, and if an agent doesn't pay its net position
in time, its locked collateral covers it.

Base is the first mainnet. Each chain added after it gets the same
cycle, the same netting and the same SDK calls, with only the network id
changed.

## What changes for you

- **New to 4Mica:** install `@4mica/x402` and `@4mica/sdk` for TypeScript,
  or `4mica-x402` and `sdk-4mica` for Python, and start from the code above.
- **Already on 4Mica v1:** upgrade to the 2.x packages and delete your tab
  configuration. In v1, a buyer had to open a tab with each seller before
  paying. v2 needs nothing opened first, so `openTab`, `extra.tabEndpoint`,
  `tabConfig` and `POST /tabs` are gone. A seller on
  `paymentMiddlewareFromConfig` and a buyer on `wrapFetchWithPaymentFromConfig`
  change nothing else.
- **Networks:** Base mainnet (`eip155:8453`) is production and Base Sepolia
  (`eip155:84532`) is the network to build against. Ethereum Sepolia is
  retired.

The [changelog](https://docs.4mica.io/updates/changelogs) lists every renamed
call, and the [docs](https://docs.4mica.io) cover the full model.

## Start building

If you sell work whose price you only know at the end, such as model calls,
crawls or agent runs, this is the release that lets you sell it per request.
Build against Base Sepolia today and point the same code at Base mainnet when
you are ready. If you run an x402 facilitator or sell API volume and want to
talk through an integration, [get in touch](mailto:support@4mica.io).
